# buy-or-rent · 买房还是租房？

用 150 年、16 国的历史数据，把"买房还是租房"从一道依赖未来预测的算术题，
变成一个输出概率的估算问题——并且给每个概率都配上置信区间。

**核心思路**：决策变量分三层——租售比、利率、税费等在决策时刻**直接可观察**；
未来房价涨幅**半可预测**（被期初估值条件化）；投资收益、通胀体制**不可约不确定**
（用历史分布代言）。算法先解出"买房打平需要的涨幅 g\*"，再回答
"这个涨幅在 1870 年以来的所有历史窗口中出现过百分之几"。所有概率均以国家为
整群（block）自助抽样给出 95% 区间——窗口高度重叠，点估计不配区间就是假装精确。

**在线计算器 → <https://ll145.github.io/buy-or-rent/>**
（填三个数：房子总价、同小区月租、打算住几年）

## 快速开始

```bash
pip install -r requirements.txt

python3 analysis/cases.py                 # 论文第7节的三个画像

python3 analysis/lookup_table.py          # 第8.4节: 租金收益率 × 持有期 速查表(含每格 95% 区间)
python3 analysis/stress.py                # 第8节: 横盘/日本路径压力表、2021 对照、g* 弹性、国家等权稳健性
python3 analysis/algorithm_figures.py     # 算法输出总览图
python3 analysis/build_web.py             # 生成单文件网页计算器
```

要估算你自己的情况，用上面的网页即可，不需要装任何东西。
`buyrent/` 包是论文数字与网页数据背后的引擎，也可以直接调用：

```python
from buyrent import History, Scenario, breakeven_growth_real, run

s = Scenario(rent_yield=0.018, mort_rate=0.040, down=0.30, hold=10)
hist = History()                  # History(since=1950) 可限定为战后窗口
print(breakeven_growth_real(s))   # 打平需要的真实年涨幅
print(run(s, hist, tercile=2))    # 胜率(含95%区间)与财富差分布
```

## 主要发现（详见 [论文初稿](paper/paper.md)）

- 1870–1950 年真实房价年涨的跨国中位数仅 **+0.3%**（12 国）；战后升至 +2.3%，
  全期 +1.2%（13 国）。数据库有 18 国，但各事实的可用子样本不同，仓库中逐处标注。
- 住房长期真实总回报 ≈7%/年，与股票相当——但其中约 5 个百分点来自**租金**，
  涨价只贡献约 1–2 个百分点。买房赚的可靠部分是省下的租金。
- 期初租售比偏离**负向预测**未来十年房价，但按重叠窗口修正后只是勉强显著
  （双向聚类 t=−2.08，p≈0.055；五年期 t=−1.71，不显著），R²≈2%。
  朴素 OLS 报出的 t≈−5 是窗口重叠制造的假象。方向可信、力度温和——
  所以诚实的答案只能是概率，不是点估计。
- 历史上所有"国家×10年"窗口中，真实房价年化涨幅 ≥2% 的只有 38%（区间 [32, 43]），
  ≥4% 的只有 18%（[14, 22]）；高估值起点之后十年下跌的概率为 42%（[35, 48]），
  低估值起点为 31%（[23, 39]）——两者之差 10.6pp 的区间 [−0.8, +21.3] 跨零，
  所以估值条件化只是温和的先验移动，不是判据。
- 经验法则：按揭 4.5%、首付三成时，**租金收益率 ≈4.2% 是买房不靠涨价
  也划算的分水岭**；持有期不足 5 年时交易成本几乎注定租房更优。
- **2026 年中国**（论文第 8 节）：房价下跌 + 按揭 3.1% + 居民投资收益率塌缩，
  买租天平较 2021 大幅回摆——二线省会（租金收益率 ≥2.3%）打平只需历史平均涨幅、
  金融账基本打平（胜率 46%，区间 [39, 54]）；一线仍偏租（26–36%）但期望代价从
  30%+ 房价缩到约一成。相邻城市档的区间大幅重叠，表支持梯度而非排序；
  三四线按耐用消费品逻辑对待；日本路径（1990 后十年年化 −2.2%）是所有城市共同的左尾。
  各城"常态租金收益率"是假设而非数据，论文 8.2 节末给出翻转门槛与换组后的胜率：
  二线的假设离门槛只有 6 个基点，换组后胜率 54%；所有敏感性都只朝利好买方的方向移动。
  含分城市 × 分年龄 × 分收入的建议矩阵，以及"租金收益率 × 持有期"二因素速查表（8.4 节）。
  中国按揭为 LPR 浮动利率，模型相应关闭了固定利率按揭的通胀对冲通道（否则胜率虚高约 20 个百分点）。
  三条命名路径把答案摊开：历史中位路径下二线打平、一线亏 6% 房价；房价横盘十年，一线亏 16%、二线亏 10%；
  日本路径（真实 −2%/年）下所有城市亏三成上下。

## 给 2026 年要做决定的人：先看这五个数

论文第 5 节按（可观察性 × 预测力）排出的关键因素，也是网页计算器的输入：

1. **你所在城市的租金收益率**（年租金 ÷ 房价）。单个最重要，完全可观察。每高 1 个百分点，买房打平所需的涨幅降 1.1 个百分点。
   2026 年：一线 1.6–1.9%，二线 2.0–2.4%；约 4.2% 才是"不靠涨价也划算"的分水岭（按揭 4.5% 时）；2026 年中国口径（按揭 3.1%）下这条线约 2.3%，二线省会正好踩在上面。
2. **持有期**。不足 5 年，交易成本几乎注定租房更优，不用看概率。
3. **真实按揭利率**。2026 年名义 3.1%、通胀约 0，真实利率约 3%，并不低。每高 1 个百分点，打平涨幅升 0.64 个百分点。
4. **租售比相对本市历史常态的偏离**。只是温和地移动未来涨幅的分布（高估起点后十年下跌概率 42%，低估起点 31%），不是判据。
5. **本地收入增速**。租金涨速的锚，但对打平涨幅的影响只有租金收益率的十分之一；它主要通过"月供不超过税后收入四成"这条红线起作用。

四条红线优先于任何概率：持有期不足 5 年不买；月供超过税后收入四成不买；掏空应急储备凑首付不买；不碰高风险期房。
网页计算器会检查前两条。

## 网页计算器

**<https://ll145.github.io/buy-or-rent/>** —— 单文件页面，把 5834 个历史窗口和完整算法都嵌在里面，打开即用，不联网也能算。
普通人只需填三个数：房子总价、同小区月租、打算住几年；选填税后月收入，页面就会检查"月供不超过收入四成"这条红线。
输出四样东西：先过红线，再看买房胜率（带 95% 区间）、打平所需涨幅及其历史频率、
以及"历史中位 / 横盘 / 日本路径"三条命名路径下你会多出或少掉多少钱（折成万元）。
判词与论文 8.4 节速查表用同一条规则：对两档租房投资收益率（你填的那档与高 1.5 个百分点的那档）同时算，两档同向才下结论；
测试保证网页判词绝不比速查表更激进。
默认口径是 2026 年的中国（浮动利率按揭、通胀 0.5%、租房者只拿存款理财级别的收益）；
把"按揭利率类型"切到固定，就换成论文第 7 节画像 B 的美式口径——通胀与股六债四回报取各历史窗口的联合实现值。
历史窗口只有 5/10/15/20 年四档，页面会标出你填的年数实际用了哪一档。
页面不外链任何字体或脚本：主要读者在中国大陆，外链 Google Fonts 会阻塞首屏。

`analysis/build_web.py` 由同一个模板产出两份：`web/index.html` 是完整文档
（带 charset 与 viewport，供 GitHub Pages 部署或本地双击打开），
`web/calculator.html` 是片段版（供 Artifact 发布，宿主会自己包一层）。
两份的内容体与嵌入数据由测试断言完全一致。

`.github/workflows/pages.yml` 在每次相关改动后由源码**重新构建**再部署，
而不是搬运仓库里的文件——线上页面因此不可能比 `windows.csv` 陈旧。

页面把模型重新实现了一遍（JavaScript）。两份实现一旦分叉，页面就会安静地
给出与论文不同的结论——所以 `tests/test_web_calculator.py` 会在 node 里跑页面
里的算法，与 Python **逐位**对照；数据也不做四舍五入导出，正是为了让这个
等价性可以断言。

## 改动约定

论文里的每个数字都由 `analysis/` 下的脚本产出并写入 `data/derived/`。
改了模型或口径，就要重跑相应脚本，并同步更新
`paper/paper.md`、`paper/paper.tex`、`README.md` 三处引用——
`tests/test_paper_consistency.py` 会强制这四者一致，对不上就测试失败。
